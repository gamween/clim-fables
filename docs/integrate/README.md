# Integrating clim with Fables

clim × Fables is a showcase, not affiliated with Fables. This page is what Fables would change, level by level, with
the exact code and calldata, and what each level costs and risks. Every address is in
[`shared/deployments/robinhood-testnet.json`](../../shared/deployments/robinhood-testnet.json); the threat model is
[`docs/security.md`](../security.md).

| Level | Fables' work | Risk to Fables | Status |
|---|---|---|---|
| 0. Shadow | None: clim's desk reads Fables' live ETH/USDG pool and publishes its own recommendation next to the keeper's overrides | None | The CRE workflow's `rh-shadow-settings` target reads the mainnet pool (read only, never a write); see [`cre/README.md`](../../cre/README.md) |
| 1. Keeper input | A few lines in the off-chain keeper: read `ClimFeePolicy` over RPC and compose with the keeper's own fee | No contract touched | Works today against the testnet desk: [`keeper-read.ts`](keeper-read.ts) |
| 2. On-chain adapter | One AccessManager batch, revocable in one call | Bounded by the hook's own floor, cap and TTL; only roles Fables grants can call `ClimPoker`; clim holds no admin power; a silent desk means no poke | Batch encoded from the ABIs and executed against Fables' real AccessManager on a mainnet fork; live on clim's own testnet pools |

## Level 1: read clim from the keeper

[`keeper-read.ts`](keeper-read.ts) is self-contained (viem only), typed and tested
([`test/keeper-read.test.ts`](test/keeper-read.test.ts)). It reads, at one block three blocks behind the head:
`ClimFeePolicy.quote()` (one fee for both directions), `quoteDirectional()` (`fee0For1`, `fee1For0`),
`lastObservation()` (the desk's `tObs` and `seq`) and `tauKillSec()`. Nothing is sent.

```bash
bun docs/integrate/keeper-read.ts
```

Expected output, here a read at block 134,955,298 (values move with the market; `mode` is `normal`, `degraded` or
`blind`):

```
{
  "fee": 1368,
  "fee0For1": 1652,
  "fee1For0": 1368,
  "mode": "normal",
  "tObs": 1791971178,
  "seq": 126,
  "ageSec": 29,
  "tauKillSec": 180,
  "blockNumber": "134955298",
  "blockTimestamp": 1791971207
}
composed with a 700-pip keeper fee: {"fee":1368,"source":"clim","climUsed":true}
```

The keeper diff, around the call it already makes:

```ts
import { createPublicClient, http } from "viem";
import { robinhoodTestnet } from "viem/chains";
import { composeFee, readClimQuote } from "./keeper-read";

const climClient = createPublicClient({ chain: robinhoodTestnet, transport: http() });

// before: await pokeFee(poolId, myFeePips, ttl)
const clim = await readClimQuote(climClient);
const { fee } = composeFee(myFeePips, clim); // max(yours, clim's) while clim is fresh; yours alone otherwise
await pokeFee(poolId, fee, ttl);
```

How it composes:

- **max, never min.** `composeFee` returns the higher of the keeper's fee and clim's `quote()`. clim can raise the
  fee, never lower the keeper's, so the keeper's event overrides (CPI, FOMC) stay on top.
- **A blind desk is ignored.** When the desk has not reported for more than `tauKillSec` (180 s), `mode` is `blind`
  and the policy's quote jumps to its safe fee (30 bp); `composeFee` then returns the keeper's fee alone, the same
  rule `ClimPoker` applies on-chain (it refuses to poke). A stricter freshness is one argument:
  `composeFee(myFeePips, clim, 60)`.
- **A degraded desk counts.** `degraded` means the venues disagree by more than 25 bp; the policy then quotes at least
  its safe fee, and `composeFee` keeps it.
- **One fee or two.** ETH/USDG's hook takes one fee for both directions: use `composeFee` with `quote()`. The newer
  per-direction hooks take two: `composeDirectional(my0For1, my1For0, clim)` composes each side with
  `quoteDirectional()`.
- **Units.** Fees are in pips: 100 pips = 1 bp; Fables' ETH/USDG band is 100 to 6,000 pips with a 700-pip flat fee.

What the keeper trusts at level 1: the testnet desk, written today by the CRE simulator with clim's operator key
(see "Honest status" below and [`docs/security.md`](../security.md)).

## Level 2: the AccessManager batch

`ClimPoker` holds FEE_POKER on the hook and is governed by Fables' own AccessManager: `poke()`, `postEvent()` and
`postEventAndPoke()` are `restricted`, so only the roles Fables assigns can call them. `poke()` sends
`max(clim's fee, live event fee)` per direction, with a TTL anchored to the desk's observation; the keeper posts its
event overrides through `postEvent` / `postEventAndPoke` so they compose with clim's fee in the hook's one override
slot ([`contracts/src/v2/ClimPoker.sol`](../../contracts/src/v2/ClimPoker.sol)).

The batch, in order (generated by [`level2-batch.ts`](level2-batch.ts) from the compiled ABIs in
[`shared/abis/`](../../shared/abis/)):

| # | Call | Effect | Needs |
|---|---|---|---|
| 1 | `grantRole(1, ClimPoker, 0)` | ClimPoker may call the hook's `pokeFee` (FEE_POKER) | POKER_ADMIN (role 5), the admin of FEE_POKER |
| 2 | `setTargetFunctionRole(ClimPoker, [postEvent, postEventAndPoke], 1)` | the keeper (FEE_POKER) posts its event overrides through ClimPoker | ADMIN (role 0) |
| 3 | `labelRole(7, "CLIM_RUNNER")` | names the new role | ADMIN |
| 4 | `setTargetFunctionRole(ClimPoker, [poke], 7)` | CLIM_RUNNER may trigger a poke (the fee still comes from the policy) | ADMIN |
| 5 | `grantRole(7, clim's runner, 0)` | clim's runner bot pokes after each desk report | ADMIN (the default admin of a new role) |
| 6 | `grantRole(7, Fables' keeper, 0)` | the keeper can poke too | ADMIN |

All six go in one transaction as `multicall(bytes[])` on the AccessManager. On Fables' AccessManager
(`0xA362D98B33A7bb5B5E2180a05f995A70FB404f30`) the deployer `0x359856655934338d798F9ccE1f181486301D36a5` holds both
ADMIN and POKER_ADMIN with no execution delay, and roles 1, 2, 4, 5 and 6 are labelled; 7 is free. To check before
sending:

```bash
RPC=https://rpc.mainnet.chain.robinhood.com
AM=0xA362D98B33A7bb5B5E2180a05f995A70FB404f30
cast call $AM "hasRole(uint64,address)(bool,uint32)" 0 0x359856655934338d798F9ccE1f181486301D36a5 --rpc-url $RPC   # true 0
cast call $AM "hasRole(uint64,address)(bool,uint32)" 5 0x359856655934338d798F9ccE1f181486301D36a5 --rpc-url $RPC   # true 0
cast call $AM "getRoleAdmin(uint64)(uint64)" 1 --rpc-url $RPC                                                       # 5
cast logs --from-block 37250000 --to-block 47249999 --address $AM "RoleLabel(uint64 indexed,string)" --rpc-url $RPC  # roles 1, 2, 4, 5, 6
```

The calldata is in [`level2-batch.fork.json`](level2-batch.fork.json) (`calls[].data`, `multicall.data`,
`revoke`), for Fables' AccessManager and the `ClimPoker` of the recorded fork run. Inspect any of it with
`cast calldata-decode "multicall(bytes[])" $(jq -r .multicall.data docs/integrate/level2-batch.fork.json)`.
For a real deployment, regenerate it with the address `ClimPoker` gets and clim's runner key:

```bash
bun docs/integrate/level2-batch.ts --access-manager 0xA362D98B33A7bb5B5E2180a05f995A70FB404f30 \
  --poker <deployed ClimPoker> --runner <clim's runner> --runner 0x1B6a8808E1D26dba66bA11E52997803C43CAd429
```

**Proved against the real AccessManager.** [`contracts/test/fork/Level2Batch.t.sol`](../../contracts/test/fork/Level2Batch.t.sol)
forks Robinhood Chain mainnet at block 87,780,000, places `ClimPoker` at the address the file names, and sends the
file's bytes as `0x3598...36a5`:


Expected: `7 tests passed, 0 failed, 0 skipped`. The tests: the multicall sets every role and the runner's poke
reaches the real hook; the six calls also work one by one; a stranger cannot send it; the revocation stops every
poke; the cleanup removes both runners; a keeper poking the hook directly is overwritten by the next clim poke (the
hook keeps one override per pool), while an event posted through `ClimPoker` survives it.

**Live on clim's testnet.** [`contracts/script/v2/13_LiveDesk.s.sol`](../../contracts/script/v2/13_LiveDesk.s.sol)
sent the same calls to clim's own AccessManager at deployment (one CLIM_RUNNER, clim's runner).
[`level2-batch.testnet.json`](level2-batch.testnet.json) is that batch, and this read-only check compares it with the
chain:

```bash

```

### Revocation

- **Stop everything, one call:** `revokeRole(1, ClimPoker)` (`revoke.stop.data`), sent by a POKER_ADMIN holder. From
  the next block every `poke()` reverts in the hook; the last override expires (at most `ttl` = 600 s after its
  observation) and the pool returns to its flat fee. Tested: `test_RevocationStopsEveryPoke`, and
  `test_RevokedRoleStopsPokes` in [`FablesFork.t.sol`](../../contracts/test/fork/FablesFork.t.sol).
- **Clean up:** `revokeRole(7, account)` for each CLIM_RUNNER (`revoke.cleanup[]`), sent by an ADMIN holder. Tested:
  `test_CleanupRemovesTheRunners`.

Fables' AccessManager puts a target admin delay on Fables' own contracts: 3,600 s on the ETH/USDG hook
(`getTargetAdminDelay(0x06a8...6080)` returns 3600). A `setTargetAdminDelay(ClimPoker, 3600)` can follow the batch if
Fables wants role changes on `ClimPoker` to wait as long. It is not in the batch: that is Fables' policy to set.

## Honest status and the path to mainnet

- **What runs today.** The desk runs in the CRE simulator (`cre workflow simulate --broadcast`) on the maintainer's
  Mac, and its reports reach `RiskDeskV2` on Robinhood Chain testnet through the `MockKeystoneForwarder` with clim's
  operator key; the desk accepts them only from that key while `simMode` is on. DON deploy access is pending.
- **Why testnet.** CRE writes to `robinhood-testnet` only today (spec §2; [`docs/feedback/cre-friction-log.md`](../feedback/cre-friction-log.md),
  row 7). Level 1 works now: a mainnet keeper can read the testnet desk over RPC. Level 2 on mainnet needs a desk on
  mainnet, so it waits for CRE writes to `robinhood-mainnet`.
- **What changes then (configuration only).** Deploy `RiskDeskV2`, `ClimFeePolicy` (parameters from
  [`shared/params-fables.json`](../../shared/params-fables.json)) and `ClimPoker` (authority: Fables' AccessManager)
  on chain 4663; point the workflow's `rh-production-settings` target at the new desk; pin the workflow id;
  `disableSim(<the KeystoneForwarder Chainlink publishes for robinhood-mainnet>)`; hand the desk's ownership to a
  timelock or renounce it; Fables sends the batch above with the new `ClimPoker` address.
- **What stays.** The contracts' code, the policy's parameters, the batch's shape and every test on this page.
